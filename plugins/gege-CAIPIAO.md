# gege_CAIPIAO

## 福利彩票 + 斗地主 + 麻将一体化系统

`gege_CAIPIAO` 是一套面向 **ESX / QB / QBOX** 的综合娱乐与彩票运营插件，提供刮刮乐、双色球、兑奖、奖池、经营收益管理，以及斗地主、麻将多人对局能力，适用于需要“即装即用、可长期运营”的 FiveM 服务器。

当前版本：**v2.1.18**

本资源重点强调：

- **稳定性**：对旧数据、旧 metadata、不同背包结构提供兼容兜底
- **可配置性**：框架、通知、目标交互、背包系统均可自动识别或手动指定
- **运营性**：支持经营收益、职业等级限制、奖池管理、自动开奖与兑奖面板
- **一体化**：彩票与桌牌游戏共用一套经营收益体系，统一 NUI 与资源启动

---

## 产品定位

`gege_CAIPIAO` 是一套更偏向**商用运营**的综合资源，核心目标是帮助服主快速搭建：

- 可持续售卖的彩票业务
- 可管理的兑奖与开奖机制
- 可追踪的经营收益与奖池体系
- 可控的权限与职业等级门槛
- 可兼容多框架、多背包的长期运行环境
- 可落地的斗地主 / 麻将桌面娱乐玩法（现金结算）

适合以下场景：

- 彩票店 / 兑奖点 / 经营收益 NPC
- 服务器内运营型活动
- 需要奖池、税收、销售额统计的经济系统
- 需要桌牌娱乐并与经营收益打通的商业区玩法
- 需要自动识别框架并尽量减少适配成本的项目

## 核心能力

### 1. 刮刮乐业务

内置 5 种刮刮乐彩票型：

- 福龙贺岁
- 富耀龙腾
- 祥龙报喜
- 中国龙
- 发财鸭

支持：

- 多玩法判定
- 多图标展示
- 自动开奖结果识别
- 兑奖员兑奖
- 批量兑奖
- 税后奖金结算

### 2. 双色球业务

支持标准双色球玩法：

- 6 红 + 1 蓝选号
- 1 - 10 倍投注
- 定时自动开奖
- 奖池累积
- 中奖记录管理
- 未兑奖票据处理

### 3. 斗地主

- 多地点、多桌子配置
- 三人入座对局
- **仅现金结算**（无筹码物品模式）
- 开局底价、入桌最低资金校验
- 输赢抽水可开关
- 底价与抽水并入经营收益 NPC
- **召唤 AI**：可手动补齐空位机器人（不强制，点「召唤AI」才填充）
- **音效 / 报牌语音**：准备、发牌、叫分、出牌、炸弹/王炸、报单报双等
- 桌子 / 椅子高度偏移可调（`Config.TableZOffset` / `Config.ChairZOffset`）
- 椅子模型：`gege_seat`（随资源 stream）
- 事件前缀：`gegeddz:`（与麻将隔离）
- UI 品牌：格格

### 4. 麻将

- 多地点、多桌子配置
- 四人入座对局
- **仅现金结算**（无筹码物品模式）
- 入场费（现金）并入经营收益
- 支持默认抽水与单桌独立抽水
- 桌子 / 椅子高度偏移可调（同斗地主全局偏移）
- 椅子模型：`gege_seat`
- 事件前缀：`gegemj:`（与斗地主隔离）
- UI 品牌：格格

### 5. 经营收益管理

提供可用于服务器商业化运营的基础能力：

- 彩票销售额统计
- 斗地主底价 / 抽水归集
- 麻将入场费 / 抽水归集
- 经营收益提取权限控制
- 职业列表限制
- 职业等级限制
- 自动建表
- 兼容旧数据回收与修复

### 6. 兼容与适配

资源支持自动识别：

- 框架：`ESX / QB / QBOX`（`auto` 顺序：**ESX → QB → QBOX**）
- 背包：`ox_inventory / qb-inventory`
- 目标交互：`ox_target / qb-target`
- 通知系统：`ox_lib / okokNotify / ps-ui / qb-core / mythic_notify / t-notify / pNotify`

## 部署要求

### 必需依赖

- `oxmysql`
- `ox_lib`
- 一个可用框架：`es_extended` / `qb-core` / `qbx_core`

### 推荐环境

- 一个可用背包：`ox_inventory` / `qb-inventory`
- 已启用数据库连接并可正常写入
- 服务器已安装并启用目标交互资源（`ox_target` / `qb-target`）
- 使用统一的通知框架，避免多通知并存

## 安装流程

1. 将 `gege_CAIPIAO` 放入 `resources` 目录（建议保持文件夹名不变）。
2. 确保依赖资源已经安装并正常启动。
3. 在 `server.cfg` 中按顺序添加：

```cfg
ensure oxmysql
ensure ox_lib
ensure gege_CAIPIAO
```

4. 按你的背包系统添加对应彩票物品。
5. 根据运营需求调整 `config.lua`（彩票坐标、牌桌坐标、价格、抽水、权限等）。
6. 重启服务器，资源会自动创建表并补齐旧表缺失字段，无需手动进数据库。

## 经营收益说明

以下金额统一进入 `GE.SalesNPC` 对应的经营收益账户：

- 彩票销售额
- 斗地主开局底价
- 斗地主输赢抽水
- 麻将入场费
- 麻将输赢抽水

由 `GE.SalesNPC.withdraw` 配置的职业可在经营收益 NPC 处查看与提取。

**防刷规则：** 上述彩票店职业玩家自己购买刮刮乐 / 双色球时，扣款照常，但**不会写入经营收益**，避免「自购 → 入账 → 提取」卡 BUG。

斗地主与麻将均只使用**玩家现金**结算，不再提供筹码物品模式。

## 业务流程

### 刮刮乐业务流程

所有刮刮乐（含中国龙）流程一致：**必须先刮开，再前往兑奖员领取奖金**，不支持购买后直接兑奖。

1. 玩家获取或购买刮刮乐彩票
2. 使用物品打开刮刮界面
3. 打开时服务端将彩票标记为 `scratched`（仅标记已刮开，**不**标记已兑奖）
4. 玩家在界面中刮开并完成结算
5. 中奖：写入中奖 metadata，保留中奖票并提示前往兑奖员；未中奖：销毁票据
6. 在兑奖员处领取税后奖金，服务端原子标记 `claimed` 并移除物品
7. 兑奖面板单张兑奖与一键批量兑奖仅处理已刮开且服务端验证通过的中奖票据

### 状态流转（`scratched` → `claimed`）

```
购买 → 使用物品打开 → scratched=1 → 刮开结算 → 中奖(metadata) → 兑奖员领取 → claimed=1
                              └→ 未中奖 → 票据销毁
```

兑奖列表条件：已刮开（`scratched`）+ 有中奖信息 + 未兑奖（`claimed=0`）。

### 状态字段说明

| 字段 | 含义 | 何时写入 |
|---|---|---|
| `scratched` | 已刮开 | 打开刮刮界面时 |
| `claimed` | 已领取奖金 | 兑奖员发钱成功时 |
| `used` | 已使用 / 已结算 | 打开界面或兑奖时 |
| `award` / `hit` | 奖金金额与是否中奖 | 购买生成时写入数据库 |

### 双色球业务流程

1. 玩家选择号码并完成投注
2. 系统记录票据并进入开奖流程
3. 到期开奖时自动开奖
4. 中奖票据可在面板中查询、兑奖或销毁

### 兑奖与结算

- 支持单张兑奖
- 支持一键批量兑奖
- 支持税后金额结算
- 支持旧卡与旧 metadata 兼容兜底

### 斗地主业务流程

1. 走近桌子，按 `E` 入座（提示：参加斗地主对局）
2. 校验现金是否满足 `Config.MinMoneyRequired`
3. 打开对局界面后点 **准备**；空位可点 **召唤AI** 补齐机器人（不自动填充）
4. 三人（真人 + AI）均准备后开局，扣除 `Config.CostPerRound` 底价（进经营收益）
5. 对局中播放音效与报牌语音（出牌、炸弹、报单/报双等）
6. 对局结束按分数 × `ratio` 结算现金；真人可顶替 AI 座位加入
7. 若启用抽水，按 `Config.TaxRate` 抽取并入经营收益
8. 点 **退出牌局** 离桌；异常入座失败会自动释放座位，避免「当前桌已满」假占位

### 麻将业务流程

1. 走近桌子，按 `E` 入座（提示：参加麻将对局）
2. 入座时扣除 `Config.MJJoinFee`（现金，进经营收益）
3. 四人齐后开始对局
4. 对局结束按分数 × `ratio` 结算现金
5. 若桌子启用 `society` 抽水，赢/输按比例抽取并入经营收益

## 兼容与容错

当前版本已针对以下问题做了额外兼容（彩票线历史能力已并入）：

- 旧卡数据字段不完整
- 旧版 metadata 结构不一致
- 不同背包系统返回结构差异
- 部分素材资源缺失或映射不一致
- 个别卡种中奖字段不统一
- 刮开、兑奖、已兑奖三阶段状态流转不一致
- 中国龙展示金额误计入中奖金额导致奖金异常
- 刮开中奖后提前标记 `claimed` 导致无法兑奖
- 打开刮刮界面时错误提前标记 `claimed` 的问题
- 未刮开的中奖卡被直接触发兑奖事件套现
- 购买数量为负数导致扣款变加钱的刷钱漏洞
- 内部事件被客户端伪造调用越权打开/查看任意彩票
- 双色球红球重复导致中奖判定异常
- 兑奖发钱与领奖标记非原子导致的重复领奖

这意味着即便是历史数据，也能尽可能按新规则识别与结算，减少运营过程中的人工干预。

### v1.5（2026-06-13）

修复玩家反馈的「中国龙买了不用刮就能直接兑奖」的 BUG。

**根因**：兑奖列表 `listPrizes` 要求 `scratched=1` 才显示，但实际发奖的 `ge_cp:cashIn`（单张）与 `ge_cp:cashInAll`（一键）事件未校验是否刮开，只查 `award>0 AND claimed=0`，导致未刮开的中奖卡可被直接触发兑奖事件套现。

| 修复项 | 说明 |
|---|---|
| 单张兑奖强制刮开 | `cashIn` 校验 `scratched=1`，未刮开提示「请先刮开彩票再兑奖」 |
| 一键兑奖强制刮开 | `cashInAll` 跳过未刮开 / 已兑奖的卡，仅结算真正刮开的中奖卡 |
| 新增校验函数 | 新增 `isCardScratched(cardId)`，统一判断是否已刮开 |

修复后所有刮刮乐（含中国龙）必须 **先刮开 → 再兑奖**，无法不刮直接兑奖。
